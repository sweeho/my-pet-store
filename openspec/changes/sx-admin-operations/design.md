# Admin Operations — Design Document

## Architecture Overview

```
Browser (HTTP)
    ↓
[AdminRequestProcessor Servlet]
    ├─ POST /admin/AdminRequestProcessor → index.jsp (admin home)
    └─ POST with currentScreen=manageorders → buildJNLP() generates JNLP
                ↓
[Rich Client (Java Swing via Web Start)]
    ├─ HttpPostPetStoreProxy connects to /admin/ApplRequestProcessor
    │   ├─ Session ID embedded in URL path (jsessionid parameter)
    │   └─ HTTP POST with XML request body
    └─ Sends GETORDERS, UPDATESTATUS, REVENUE, ORDERS requests
                ↓
[ApplRequestProcessor Servlet - Rich Client Backend Handler]
    ├─ Receives XML request
    ├─ Parses request type (GETORDERS, UPDATESTATUS, REVENUE, ORDERS)
    ├─ Delegates to AdminRequestBD for business logic
    ├─ Returns XML response
    └─ [AdminRequestBD]
         ├─ getOrdersByStatus() → OPCAdminFacade EJB
         ├─ updateOrders() → AsyncSender EJB (async notification)
         └─ getChartInfo() → Database queries for revenue/order data
```

## Request/Response Protocol

All requests are XML-encoded and sent via HTTP POST. The system defines four request types:

### GETORDERS Request
**Input XML:**
```xml
<Request>
  <Type>GETORDERS</Type>
  <Status>PENDING</Status>
</Request>
```
**Output XML:**
```xml
<Response>
  <Type>GETORDERS</Type>
  <Status>PENDING</Status>
  <TotalCount>42</TotalCount>
  <Order>
    <OrderId>O12345</OrderId>
    <UserId>customer_7</UserId>
    <OrderDate>2025-09-01</OrderDate>
    <OrderAmount>299.99</OrderAmount>
    <OrderStatus>PENDING</OrderStatus>
  </Order>
  ...
</Response>
```

### UPDATESTATUS Request
**Input XML:**
```xml
<Request>
  <Type>UPDATESTATUS</Type>
  <Order>
    <OrderId>O12345</OrderId>
    <OrderStatus>APPROVED</OrderStatus>
  </Order>
  <Order>
    <OrderId>O12346</OrderId>
    <OrderStatus>DENIED</OrderStatus>
  </Order>
</Request>
```
**Output XML:**
```xml
<Response>
  <Type>UPDATEORDERS</Type>
  <Status>SUCCESS</Status>
</Response>
```

### REVENUE Request
**Input XML:**
```xml
<Request>
  <Type>REVENUE</Type>
  <Start>09/01/2025</Start>
  <End>09/30/2025</End>
  <ReqCategory>BIRDS</ReqCategory>
</Request>
```
**Output XML:**
```xml
<Response>
  <Type>REVENUE</Type>
  <Start>09/01/2025</Start>
  <End>09/30/2025</End>
  <ReqCategory>BIRDS</ReqCategory>
  <Item name="Parrot">1250.00</Item>
  <Item name="Canary">450.00</Item>
  <TotalSales>1700.00</TotalSales>
</Response>
```

### ORDERS Request
**Input XML:** (same structure as REVENUE)
**Output XML:** (similar to REVENUE, but integer quantities)
```xml
<Response>
  <Type>ORDERS</Type>
  ...
  <Item name="Parrot">5</Item>
  <Item name="Canary">8</Item>
  <TotalSales>13</TotalSales>
</Response>
```

## JNLP Generation

The AdminRequestProcessor servlet generates a dynamic JNLP file when the rich client is launched:

**JNLP Content (generated by buildJNLP()):**
```xml
<?xml version="1.0" encoding="UTF-8"?>
<jnlp spec="1.0+"
  codebase="http://servername:port/admin/"
  href="launch.jnlp">
  <information>
    <title>Java Pet Store Admin</title>
    <description>Order Management Rich Client</description>
  </information>
  <security><all-permissions/></security>
  <resources>
    <j2se version="1.4+" href="http://java.sun.com/products/autodl/j2se"/>
    <jar href="admin-client.jar"/>
    ...
  </resources>
  <application-desc main-class="com.sun.j2ee.blueprints.admin.client.MainFrame">
    <argument>servername</argument>
    <argument>port</argument>
    <argument>SESSION_ID</argument>  <!-- Embedded session ID -->
  </application-desc>
</jnlp>
```

The session ID is embedded in the JNLP arguments so the rich client can authenticate to subsequent requests without re-login.

## Session Management

- **Session Timeout**: 54 minutes of inactivity
- **Session ID Persistence**: Embedded in HTTP request URL as jsessionid parameter
- **Session Validation**: ApplRequestProcessor checks for valid session; returns error if null

## Date Format & Parsing

Report date inputs must be in **mm/dd/yyyy** format:
- Input: "09/15/2025"
- Parsed via StringTokenizer with "/" delimiter
- Converted to Date object using deprecated Date constructor: `new Date(year-1900, month-1, day)`

**Example parsing:**
```
Input: "09/15/2025"
Tokens: [09, 15, 2025]
Month = 09 - 1 = 8 (September, 0-indexed)
Day = 15
Year = 2025 - 1900 = 125
Result: Date(125, 8, 15)
```

## Report Data Aggregation

Reports aggregate order data into two categories:
1. **By Category** (no ReqCategory specified): Groups data by product category (BIRDS, CATS, DOGS, FISH, REPTILES)
2. **By Item** (ReqCategory specified): Groups data by individual product/item within the category

**REVENUE Report Aggregation:**
- Sum order amounts by category/item
- Return float values
- Include TotalSales = sum of all amounts

**ORDERS Report Aggregation:**
- Count order quantities by category/item
- Return integer values
- Include TotalSales = sum of all quantities

## Order Status Values

Valid order statuses (from PetStoreProxy.Order constants):
- **PENDING** — Order awaiting administrator approval or denial
- **APPROVED** — Order approved by administrator
- **DENIED** — Order denied by administrator
- **COMPLETED** — Order fulfillment complete

## Error Handling

**Session Timeout:**
```xml
<Response>
  <Error>Session Timed Out; Please exit and login as admin from the login page</Error>
</Response>
```

**Invalid Request Type:**
```xml
<Response>
  <Error>Unable to process request : Unknown request type - INVALID</Error>
</Response>
```

**Exception During Processing:**
```xml
<Response>
  <Error>Exception while processing : [error message]. Please try again</Error>
</Response>
```

## Asynchronous Order Approval Notifications

When orders are approved or denied:
1. ApplRequestProcessor.updateOrders() parses the request
2. AdminRequestBD.updateOrders() creates an OrderApproval object (XML-serialized)
3. AsyncSender EJB is looked up via ServiceLocator
4. AsyncSender.sendAMessage(orderApprovalXml) sends to message queue
5. Message-driven beans process the notification asynchronously

This ensures the rich client doesn't block waiting for notifications to be delivered.

## Known Issues & Ambiguities

1. **Date Constructor Deprecation**: The code uses deprecated Date constructor `new Date(year, month, day)`. This should be replaced with Calendar or java.time APIs.

2. **No Transport Security**: web.xml transport-guarantee is "NONE", meaning HTTP is used. In production, this should be changed to "CONFIDENTIAL" to enforce HTTPS.

3. **Hard-coded Date Format**: The mm/dd/yyyy format is inferred from tokenization pattern; no configuration or documentation found.

4. **No Input Validation**: The ApplRequestProcessor does not validate date values before parsing (e.g., month > 12, day > 31).

5. **No Category Validation**: Report requests can specify any category value; no check against the valid category list.

6. **Response Buffering**: Large report results are buffered in StringBuffer before sending; this could cause memory issues for very large datasets.

## Deployment Considerations

- Rich clients maintain connection to ApplRequestProcessor servlet with embedded session ID
- JNLP codebase points to web server; all JAR files must be accessible via HTTP
- AsyncSender EJB must be deployed and accessible via JNDI lookup
- OPCAdminFacade EJB must be deployed for order retrieval
- Database must support the report aggregation queries
