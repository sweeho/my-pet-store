## Requirements

### Requirement: Accept order information with billing and shipping addresses

The system SHALL accept customer billing and shipping address information through an order placement form.

#### Scenario: Order form captures billing address

- **GIVEN** a customer on the order information form
- **WHEN** the customer enters first name, last name, street address, city, state, postal code, country, telephone, and email for billing
- **THEN** the form SHALL accept and store the billing address information

#### Scenario: Order form captures shipping address

- **GIVEN** a customer on the order information form
- **WHEN** the customer enters first name, last name, street address, city, state, postal code, country, telephone, and email for shipping
- **THEN** the form SHALL accept and store the shipping address information

### Requirement: Generate unique order IDs starting from seed value

The system SHALL assign each new order a unique ID generated by UniqueIdGenerator with initial seed value 1001.

#### Scenario: First order receives ID 1001

- **GIVEN** a new order placement
- **WHEN** UniqueIdGenerator creates the order ID
- **THEN** the order SHALL be assigned ID 1001

#### Scenario: Subsequent orders receive incremented IDs

- **GIVEN** an order with ID 1001 already created
- **WHEN** a new order is placed
- **THEN** the new order SHALL receive ID 1002, and the next order SHALL receive 1003

### Requirement: Record order date as current date at placement time

The system SHALL include the current date and time as the order date when order is placed.

#### Scenario: Order captures current date

- **GIVEN** an order being placed on September 8, 2026
- **WHEN** the order is created
- **THEN** the order.poDate SHALL be set to September 8, 2026

### Requirement: Create line items from shopping cart contents

The system SHALL create line items for each item in the customer's shopping cart, including quantity, unit price, and item identifiers.

#### Scenario: Line items are created for each cart item

- **GIVEN** a shopping cart with 3 items (item IDs: 001, 002, 003)
- **WHEN** the order is placed
- **THEN** the system SHALL create 3 line items with quantities and unit prices from the cart

#### Scenario: Line items include category and product identifiers

- **GIVEN** cart items with category and product hierarchy
- **WHEN** line items are created
- **THEN** each line item SHALL include categoryId, productId, and itemId

### Requirement: Clear shopping cart after successful order placement

The system SHALL remove all items from the customer's shopping cart upon successful order creation.

#### Scenario: Cart is cleared after order placement

- **GIVEN** a shopping cart with items before order placement
- **WHEN** the order is successfully placed
- **THEN** the shopping cart SHALL be empty (cart.count = 0)

### Requirement: Validate cart is not empty before order placement

The system SHALL raise ShoppingCartEmptyOrderException if order placement is attempted with an empty cart.

#### Scenario: Empty cart prevents order placement

- **GIVEN** a customer with an empty shopping cart
- **WHEN** the customer attempts to proceed to checkout
- **THEN** the system SHALL raise ShoppingCartEmptyOrderException and redirect to cart page

#### Scenario: Non-empty cart allows order placement

- **GIVEN** a customer with items in the shopping cart
- **WHEN** the customer submits the order form
- **THEN** the order SHALL be created successfully

### Requirement: Order information form displays with billing and shipping sections

The order information screen SHALL display two sections: "Billing Information" and "Shipping Information", each with first name, last name, street address (two fields), city, state/province dropdown, postal code, country dropdown, telephone, and email fields.

#### Scenario: Order form displays billing information section

- **GIVEN** a customer accessing the order placement form
- **WHEN** the form is displayed
- **THEN** a "Billing Information" section SHALL show fields for: first name, last name, street1, street2, city, state, postal code, country, telephone, email

#### Scenario: Order form displays shipping information section

- **GIVEN** the order placement form is displayed
- **WHEN** the customer views the form
- **THEN** a "Shipping Information" section SHALL show the same fields as billing information for shipping address entry

#### Scenario: Form contains valid state options

- **GIVEN** the state/province dropdown in order information form
- **WHEN** the customer clicks the dropdown
- **THEN** the dropdown SHALL display options: California (CA), New York (NY), Texas (TX)

#### Scenario: Form contains valid country options

- **GIVEN** the country dropdown in order information form
- **WHEN** the customer clicks the dropdown
- **THEN** the dropdown SHALL display options: United States, Canada, Japan, China

### Requirement: Enforce field length constraints on order information form

The order information form SHALL enforce field length constraints: names (30 characters), addresses (70 characters), postal code (20), telephone (20), email (50).

#### Scenario: First name field limits to 30 characters

- **GIVEN** the first name input field on order form
- **WHEN** a customer enters text longer than 30 characters
- **THEN** the field SHALL reject input exceeding 30 characters (maxlength="30")

#### Scenario: Address field limits to 70 characters

- **GIVEN** the street address input field
- **WHEN** a customer enters text longer than 70 characters
- **THEN** the field SHALL reject input exceeding 70 characters (maxlength="70")

### Requirement: Order confirmation screen displays order ID and email

Upon successful order placement, the system SHALL display a confirmation screen with the order ID and customer email address, confirming that a confirmation email will be sent.

#### Scenario: Confirmation screen shows order ID

- **GIVEN** a successfully placed order with ID 1005
- **WHEN** the order confirmation screen is displayed
- **THEN** the screen SHALL show "Your order Id is 1005" (using orderresponse.orderId)

#### Scenario: Confirmation screen shows customer email

- **GIVEN** an order placed by customer user@example.com
- **WHEN** the confirmation screen is displayed
- **THEN** the screen SHALL show "You should receive a confirmation e-mail soon at user@example.com"

#### Scenario: Confirmation indicates email will be sent

- **GIVEN** the order confirmation screen
- **WHEN** displayed after order placement
- **THEN** a message SHALL confirm "You should receive a confirmation e-mail soon at [email address]"
