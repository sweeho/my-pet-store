# PLAN — SWHM-T-0004 · Bootstrap the application from the boilerplate

Sprint: SWHM-S-0001 · Change: `swhm-i-0001-bootstrap-my-pet-store` · Capability: `application-foundation`

Read `openspec/changes/swhm-i-0001-bootstrap-my-pet-store/design.md` before starting. It carries the measured state of this repository, the decisions (D1–D6) and the phase order this plan cites. Do not re-derive them here.

## Design reference

The idea SWHM-I-0001 carries **no design blocks** — `a2a_get_idea_design` returned an empty manifest, so there is nothing under `artifacts/SWHM-S-0001/design/` and no mockup to match. The home page's visual treatment is the boilerplate's existing hero layout with product copy substituted; the design system is unchanged (design.md — D6).

## Objective

Turn the generated boilerplate into My Pet Store with the smallest set of changes that makes the product name true everywhere it is readable, and prove the stack end to end: clean-checkout build, static checks, unit and integration tests, browser smoke, and a green CI check run on the sprint branch.

## Steps

Phases and their rationale are in design.md — Phases. Follow that order; the numbering below matches it and matches `tasks.md`.

1. **Identity** (design.md — Phases §1; decisions D2, D3)
   - `package.json` → `name: "my-pet-store"`. Nothing else in that file.
   - `index.html` → `<title>My Pet Store</title>`.
   - `src/constants/index.ts` → `STORE_NAME = "My Pet Store"`, replacing the `Your Store-Name` placeholder.
   - Create `public/manifest.webmanifest` with at least `name` and `short_name`. `index.html` already links it; the file is absent today (design.md — Context).

2. **Home page** (design.md — Phases §2)
   - In `src/pages/index.tsx`, replace the hero heading, the eyebrow ("The boilerplate behind Vortex.") and the body copy so the level-1 heading reads "My Pet Store", sourced from `STORE_NAME`.
   - Update the two nav `sr-only` brand labels and the tech-stack chip list so no template copy survives.
   - Keep the layout, Tailwind classes, `@headlessui` Dialog and the responsive structure exactly as they are — the E2E suite asserts no vertical scrollbar at three viewport sizes and drives the mobile nav open and closed.

3. **Test harness** (design.md — Phases §3; decision D5)
   - `src/pages/index.test.tsx:20` currently pins `/Vortex: the AI-driven autonomous/`; repoint it at the new heading. The tech-stack assertion in the same file must match whatever chip list step 2 leaves behind.
   - `e2e/home.spec.ts:17` asserts the h1 contains "Vortex"; repoint it.
   - No new test tier, no new harness config — the boilerplate already ships one worked example per tier and Vitest's `client`/`server` project split already routes them (design.md — Phases §3).
   - If the new manifest changes what the browser logs, `e2e/smoke.spec.ts` is in your ownership map; its `consoleErrors` assertion is the detector (design.md — Risks).

4. **Clean-checkout build** (design.md — Phases §4)
   - Confirm the build path works with no generated files present. `auto-imports.d.ts` is generated by the `prebuild`/`pretypecheck` hooks and is absent on a fresh clone — do not commit it and do not add a tsc-only script without the same hook.

5. **Continuous integration** (design.md — Phases §5; decision D4)
   - Do **not** add a workflow. `.github/workflows/ci.yml` exists and already matches `vortex/**` on push and pull_request.
   - Correct its stale header comment ("CI for the boilerplate ITSELF").
   - Push to your ticket branch and wait for the verdict with `a2a_await_ci`. The browser tier cannot run in an engineer container — the preflight will tell you Chromium is missing. That is expected; say so and let CI prove it.

## File / module ownership

May create or modify — nothing else:

| Path                          | Why                                                       |
| ----------------------------- | --------------------------------------------------------- |
| `package.json`                | `name` field only                                         |
| `index.html`                  | `<title>`                                                 |
| `public/manifest.webmanifest` | NEW — resolves the link `index.html` already carries      |
| `src/constants/index.ts`      | `STORE_NAME`                                              |
| `src/pages/index.tsx`         | hero copy, nav brand labels, chip list                    |
| `src/pages/index.test.tsx`    | assertions pinning the hero                               |
| `e2e/home.spec.ts`            | assertion pinning the hero heading                        |
| `e2e/smoke.spec.ts`           | only if the manifest changes console output               |
| `.github/workflows/ci.yml`    | header comment; adjustment only if needed for a green run |

Out of ownership: the repository-root narrative documents (already at target state on the planning branch — do not touch them), anything under `openspec/` (including ticking a `tasks.md` box — the platform stamps those server-side on merge) or `artifacts/`, `README.md`, `db/`, `routes/`, `middleware/`, `src/helpers/`, `src/index.css`, `bun.lock`, and every deployment file.

**Fixed interface contracts** — do not change:

- `/api/hello`, `/api/users` and `/api/users/[id]` response shapes. `e2e/smoke.spec.ts` asserts `/api/users` returns an object with a `users` property, and that probe is deliberate regression cover for the Bun-runtime constraint.
- `db/schema.ts` — the `users` table stays as it is this sprint.
- The Vitest two-project split in `vitest.config.ts` (`routes/**/*.test.ts` → node, everything else → jsdom) and the `serverDir` / `exclude` / `ignore` settings in `vite.config.ts`.
- `playwright.config.ts` — port 5178, `--strictPort`, and the `bun --bun ./node_modules/vite/bin/vite.js` web server command. Losing the `--bun` breaks every database-backed route while leaving static pages green.
